Introduction to databases

1. What is a database?

A database is an organized collection of data stored so that people and programs can find, add, change, and remove information quickly. Think of a school's filing room, but searchable in a fraction of a second.

Most databases are built from tables. The student table above has three parts you will see throughout this site:

TableA group of related data about one kind of thing, such as students.
Record (row)One complete entry, such as everything about Mei Tanaka.
Field (column)One type of fact, such as Major or GPA.

2. Why are databases important?

Without a database, information ends up scattered across papers, files, and inboxes. Databases solve that:

Fast searchingFind one student among a million in moments.
Accurate dataRules stop bad entries, such as a GPA of 9.5 or a duplicate ID.
Shared accessMany people use the same up-to-date data at once.
Security and backupOnly approved users see data, and copies protect against loss.

3. What is a Database Management System (DBMS)?

A DBMS is the software that sits between people and the stored data. It creates the database, controls who can use it, answers questions (queries), and keeps the data safe and consistent. Examples include MySQL, PostgreSQL, Oracle, Microsoft SQL Server, and SQLite.

Users never touch the files directly. They ask the DBMS, and it does the work.

4. How are databases different from spreadsheets?

Both store rows and columns, so they look alike. They behave very differently once the data grows or many people need it.

SpreadsheetDatabase
Best forCalculations, charts, small listsLarge, connected data that changes often
SizeSlows down with hundreds of thousands of rowsHandles millions of records
Many usersEdits can clash or overwrite each otherMany people edit safely at the same time
Data rulesAny value can go in any cellTypes and rules reject invalid data
RelationshipsData is often repeated across sheetsTables link through keys, so data is stored once
SearchingFilters and lookupsPowerful queries written in SQL
SecurityWhole-file accessPermissions per user, table, or field

Example: a spreadsheet can list students. A database can also connect each student to their courses, grades, and bills without copying their name everywhere.

Database structure and relationships

A database stores more than one list. It splits information into separate tables and connects them. These six ideas explain how.

Tables

A table holds data about one kind of thing. A student database might have a Students table and a Majors table.

Rows and columns

Rows run across the table and columns run down it. Together they form a grid, like a spreadsheet.

Records and fields

A record is one row: everything about one student. A field is one column: one kind of fact, such as Name.

Primary key

A field that gives every record a unique identity. Student ID is the primary key of Students. No two students can share it, and it can never be empty.

Foreign key

A field that holds the primary key of a record in another table. Major ID in Students is a foreign key that points into Majors.

Relationships

A relationship is the link between two tables, made by matching a foreign key to a primary key.

Two related tables

Instead of typing "Computer Science" next to every student, the Students table stores a short code, the Major ID. The full name lives once in the Majors table. Select a student row to see which major it points to.

How Major ID connects the tables: the Major ID in each student row matches exactly one Major ID in the Majors table. John Smith has CS01, so the database looks up CS01 in Majors and finds Computer Science. If the school renames that major, you change one row in Majors and every student is updated automatically.

Sara Lopez is an extra example, added so you can see two students sharing one major.

One-to-many relationship: majors and students

One major can have many students, but each student here belongs to only one major. The "one" side is Majors, and the "many" side is Students. The foreign key always sits on the "many" side.

The single bar means "one". The three-pronged end (a crow's foot) means "many".

Other relationship types

One-to-oneOne record matches exactly one record, such as a student and their single student ID card.
One-to-manyOne record matches many, such as one major with many students.
Many-to-manyMany match many, such as students and courses. It needs a third "link" table, such as Enrollments.

Interactive SQL demonstration

SQL (Structured Query Language) is the language used to talk to a relational database. You write a short statement that says what you want, and the DBMS figures out how to do it. These seven pieces cover most everyday database work.

CREATE TABLE

Builds a new table and defines its columns.

CREATE TABLE Courses ( CourseID VARCHAR(6) PRIMARY KEY, Title VARCHAR(40));

INSERT INTO

Adds new records to a table.

INSERT INTO Students VALUES ('006', 'Sara Lopez', 'Computer Science');

SELECT

Retrieves records without changing them.

SELECT Name, Major FROM Students;

UPDATE

Changes values in records that already exist.

UPDATE Students SET Major = 'Data Science' WHERE StudentID = '001';

DELETE

Removes records from a table.

DELETE FROM Students WHERE StudentID = '005';

WHERE

Filters which records a command applies to.

SELECT * FROM Students WHERE Major = 'Cybersecurity';

ORDER BY

Sorts the results, ASC (A to Z) or DESC (Z to A).

SELECT * FROM Students ORDER BY Name DESC;

Database types and applications

Not every database is built the same way. The right choice depends on what the data looks like, how much there is, and how it will be used. Select a category to explore it.

Relational databases

Definition: A relational database stores data in tables of rows and columns, and connects the tables using keys. It is queried with SQL. This is the kind of database you built in the previous sections.

Main characteristics

  • Fixed structure (schema) defined in advance
  • Tables linked by primary and foreign keys
  • Transactions follow ACID rules
  • Uses SQL

Advantages

  • Strong accuracy and data integrity
  • Powerful queries that combine tables
  • Mature, well-supported tools
  • Reliable for important records

Common applications

  • Banking and accounting
  • Student information systems
  • Inventory and order management
  • Hospital records
Example technologies:MySQLPostgreSQLMicrosoft SQL ServerOracle Database

NoSQL databases

Definition: NoSQL ("not only SQL") databases store data in flexible formats instead of fixed tables. Common models are documents, key-value pairs, wide columns, and graphs.

Main characteristics

  • Flexible or no fixed schema
  • Several data models to choose from
  • Designed to spread across many servers
  • Often tuned for speed and volume

Advantages

  • Easy to change as data evolves
  • Handles very large amounts of data
  • Very fast reads and writes
  • Fits data that is not table-shaped

Common applications

  • Social media feeds
  • Real-time apps and gaming
  • Caching and session storage
  • Product catalogs and IoT data
Example technologies:MongoDB (document)Redis (key-value)Apache Cassandra (wide-column)Neo4j (graph)

Cloud databases

Definition: A cloud database runs on a cloud provider's servers and is used over the internet, usually as a managed service. It can be relational or NoSQL. The word "cloud" describes where it runs, not how the data is organized.

Main characteristics

  • The provider runs the hardware
  • Backups and updates are handled for you
  • Pay for what you use
  • Reachable from anywhere

Advantages

  • Little setup or maintenance
  • Easy to grow or shrink on demand
  • Built-in backup and high availability
  • No servers to buy

Common applications

  • Web and mobile apps
  • Startups and online services
  • Software-as-a-service products
  • Sites with seasonal traffic
Example technologies:Amazon RDSAzure SQL DatabaseGoogle Cloud SQLMongoDB Atlas

Distributed databases

Definition: A distributed database is one logical database whose data is spread across several servers, often in different locations, that work together as a single system.

Main characteristics

  • Data is split (sharded) across servers
  • Copies (replicas) are kept on several servers
  • No single point of failure
  • Must balance consistency against availability

Advantages

  • Keeps running if a server fails
  • Grows by adding more servers
  • Faster access by keeping data near users
  • Handles huge workloads

Common applications

  • Global online stores
  • Video and music streaming
  • Messaging platforms
  • Worldwide financial systems
Example technologies:Apache CassandraCockroachDBGoogle Cloud Spanner

Relational vs NoSQL

RelationalNoSQL
Data modelTables with rows and columnsDocuments, key-value, wide-column, or graph
SchemaFixed and defined before data is addedFlexible and easy to change
Query languageSQLVaries by product, such as MongoDB's own query language
RelationshipsStrong, using primary and foreign keys and joinsOften handled by nesting data or in the application
ScalingTraditionally by upgrading one bigger serverTypically by adding more servers
ConsistencyStrong ACID transactionsOften relaxed (eventual consistency) for speed, though it varies
Best forStructured data where accuracy matters mostLarge, fast-changing, or varied data
ExamplesMySQL, PostgreSQL, SQL ServerMongoDB, Redis, Cassandra

The same student, stored two ways:

Relational: a row in a table

StudentID | Name       | Major
001       | John Smith | Computer Science

NoSQL: a document (MongoDB style)

{
  "studentId": "001",
  "name": "John Smith",
  "major": "Computer Science",
  "clubs": ["Chess", "Robotics"]
}

The categories overlap, and the gap is shrinking. PostgreSQL can store JSON documents, MongoDB supports transactions, and a database can be both cloud-hosted and distributed. Many real systems combine several types.
